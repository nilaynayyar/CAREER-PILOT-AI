## 1. Search Methodology & Scope

Our search focused exclusively on public, legally accessible datasets that support the supervised multi-class classification problem:

$$\text{Student / Individual Profile Characteristics} \longrightarrow \text{Career Category / Job Role}$$

### Inclusion Criteria
- Tabular format (CSV, Parquet, or TSV).
- Explicit target column representing career categories or job roles.
- Features capturing student-facing or candidate-facing attributes (skills, academic indicators, interests, proficiencies).
- Permissive, verifiable open-source or academic license (CC0, CC-BY, Open Data).
- Realistic, non-trivial sample size capable of supporting 5-fold stratified cross-validation.

### Strict Exclusion Filters (Rejected by Design)
- **Student Grade / Performance Prediction** (e.g., predicting G3 exam marks or GPA).
- **Student Dropout Prediction** (e.g., predicting binary college dropouts).
- **Employee Attrition Datasets** (e.g., IBM HR Attrition dataset, which models corporate turnover, not career guidance).
- **Salary Prediction** (regression models predicting annual compensation).
- **Synthetic Rule-Generated Datasets** (datasets explicitly generated by heuristics or LLM prompts).
- **Unlicensed / Unverified Scrapings** without identifiable provenance.

## 3. Detailed Candidate Analysis & Project Fit

---

### Candidate 1: Student Career Prediction using RIASEC Dataset
- **Publisher / Author**: S. Venkatesh Kumar
- **Platform / URL**: `https://www.kaggle.com/datasets/svenkatesh/student-career-prediction-using-riasec`
- **License**: CC0: Public Domain
- **Target Audience**: Students aged 16–22 (late secondary to early undergraduate)
- **Documented Features**:
  - Academic scores: `Math_Score`, `Science_Score`, academic averages.
  - Core competencies: `Programming_Skill`, `Communication_Skill`, `Logical_Ability`.
  - RIASEC Psychometric Dimensions: Realistic (R), Investigative (I), Artistic (A), Social (S), Enterprising (E), Conventional (C).
- **Target Variable**: Multi-class career category label.

#### Project Fit Evaluation
1. **Can it directly train our CareerPilot ML classifier?**  
   Yes. It directly models student competencies and interests to recommended career categories.
2. **What would the model input be?**  
   Numeric scores (0–100 or 1–10) across academic subjects, technical proficiency ratings, and RIASEC dimension scores.
3. **What would the model output be?**  
   Probabilistic distribution across suitable career disciplines (e.g., Software Engineering, Data Analytics, Creative Design, Research, Management).
4. **What important student information is missing?**  
   Granular technology frameworks (e.g., React vs. PyTorch) and specific project deliverables.
5. **Would preprocessing be required?**  
   Yes: Standard scaling of continuous scores, verification of range bounds, and label encoding of target classes.
6. **Is there likely to be class imbalance?**  
   Moderate. Author documentation claims stratified balancing, but empirical distribution must be verified via `inspect_dataset.py`.
7. **Is there likely to be leakage?**  
   Low risk. Features reflect student assessments taken prior to career selection.
8. **Could it be academically defensible for a student project?**  
   High. Holland’s RIASEC model is an internationally validated vocational psychology framework.

### Candidate 2: Career Prediction Dataset ("Suggested Job Role")
- **Publisher / Origin**: Kaggle (`utkarshx27` / mirrors in educational research papers)
- **Platform / URL**: `https://www.kaggle.com/datasets/utkarshx27/career-prediction-dataset`
- **License**: CC0: Public Domain
- **Target Audience**: Engineering & Computer Science undergraduates
- **Documented Features**:
  - Cognitive / Analytical: Logical quotient rating, coding skills rating, public speaking rating.
  - Practical Activities: Hackathons attended, workshops attended, technical certifications, reading/writing competencies.
  - Personality & Working Style: Preference for management vs. technical tracks, working in teams vs. solo.
- **Target Variable**: `Suggested Job Role` (e.g., *Database Developer, Web Developer, Applications Developer, Security Analyst, Data Scientist, Technical Support, Software Engineer*).

#### Project Fit Evaluation
1. **Can it directly train our CareerPilot ML classifier?**  
   Yes. It was specifically created for student career role prediction within computing and engineering domains.
2. **What would the model input be?**  
   A combination of numerical skill ratings, integer activity counters (hackathons, workshops), and categorical preferences.
3. **What would the model output be?**  
   A multi-class prediction among 12–30 specific technology roles with top-$k$ ranking capabilities.
4. **What important student information is missing?**  
   Formal degree branch title (it assumes computing background) and non-technical career branches.
5. **Would preprocessing be required?**  
   Yes: One-Hot Encoding for categorical preferences, robust scaling or standard scaling for skill ratings, and label encoding for the target.
6. **Is there likely to be class imbalance?**  
   Moderate to high. Certain specialized roles (e.g., Security, QA) often have fewer records than generalist software developer roles.
7. **Is there likely to be leakage?**  
   Potential concern: Some variants include columns like "interested career area" which can be tautological with the target. Must run `inspect_dataset.py` to audit correlation.
8. **Could it be academically defensible for a student project?**  
   High, provided that we audit against data leakage and verify that records are not pre-oversampled.

### Candidate 3: Candidate Job Role Dataset
- **Publisher / Origin**: Kaggle (`sreeramkashyap`)
- **Platform / URL**: `https://www.kaggle.com/datasets/sreeramkashyap/candidate-job-role-dataset`
- **License**: CC0: Public Domain
- **Target Audience**: Job applicants & career switchers
- **Documented Features**:
  - `Skills`: Comma-separated or listed technical keywords (e.g., Python, Docker, React, AWS).
  - `Experience_Level`: Entry (0–2 yrs), Mid (3–5 yrs), Senior (6+ yrs).
  - `Qualifications`: Degree level (B.Tech, M.S., etc.).
- **Target Variable**: Target Job Role (multi-class technical roles).

#### Project Fit Evaluation
1. **Can it directly train our CareerPilot ML classifier?**  
   Yes, but requires multi-hot encoding / vectorization of text skill tags.
2. **What would the model input be?**  
   High-dimensional sparse binary matrix of candidate skills + categorical experience level.
3. **What would the model output be?**  
   Target job role category.
4. **What important student information is missing?**  
   Lacks academic performance, psychometric inclinations, and subject preferences (focuses strictly on professional resumes).
5. **Would preprocessing be required?**  
   Substantial: MultiLabelBinarizer / CountVectorizer for skill strings, ordinal encoding for experience level.
6. **Is there likely to be class imbalance?**  
   Likely high, reflecting real-world resume market distributions.
7. **Is there likely to be leakage?**  
   Low risk unless current job title is included.
8. **Could it be academically defensible for a student project?**  
   Moderate. Better for a resume-parsing ATS than an early-stage student advisory tool.

## 4. Supplementary Occupational Data: The Role of O*NET

A critical architectural requirement is distinguishing between the **ML training dataset** and the **Occupational Knowledge Base**.

### What is O*NET?
The **Occupational Information Network (O*NET)** is sponsored by the **U.S. Department of Labor, Employment and Training Administration (USDOL/ETA)** and licensed under **Creative Commons Attribution 4.0 International (CC BY 4.0)**. It serves as the world's most authoritative, empirical taxonomy of job roles, competencies, tools, and educational baselines.

### Key O*NET Tables
1. **`Technology Skills.txt`**: Maps 1,000+ Standard Occupational Classification (SOC) occupations to specific software, programming languages, and industry tools (e.g., Python, Docker, Tableau, TensorFlow).
2. **`Skills.txt` & `Knowledge.txt`**: Standardized ratings (Importance and Level, 0–100 scale) for foundational abilities (e.g., Mathematics, Systems Analysis, Critical Thinking).
3. **`Job Zones.txt`**: Required education, vocational training, and experience levels for each career path.

### Architectural Separation in CareerPilot AI

```text
[STUDENT ASSESSMENT INPUT]
          │
          ▼
┌───────────────────────────────────────────────┐
│     ML Classifier (Trained on Candidate Data) │
│  • Input: Student profile, marks, ratings     │
│  • Output: Predicted Career (e.g. Data Analyst)│
└───────────────────────┬───────────────────────┘
                        │
                        ▼ Predicted Career Role
┌───────────────────────────────────────────────┐
│    O*NET Knowledge Base (Supplementary Data)   │
│  • Input: Predicted Career Role               │
│  • Output: Benchmark Tech Skills & Tools Req. │
└───────────────────────┬───────────────────────┘
                        │
                        ▼ Benchmark Requirements + Student's Current Skills
┌───────────────────────────────────────────────┐
│         Skill Gap Agent & Roadmap Agent       │
│  • Computes Delta: [Benchmark] - [Student]    │
│  • Identifies High-Priority Missing Tools     │
│  • Sequences Milestones into 3-Phase Roadmap  │
└───────────────────────────────────────────────┘
```

> **Conclusion on O*NET**: O*NET should **not** be used to train the supervised classifier because it does not contain individual student records. Instead, it should serve as an immutable, authoritative **reference knowledge base** to ground the **Skill Gap Agent** and **Roadmap Agent** in Phase 5.
